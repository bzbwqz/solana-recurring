HOW TO DEPLOY

Devnet first. Mainnet with a new configuration.

The image runs the Portal and billing worker. GitHub Pages only hosts this documentation.

Do not use real funds for first-time testing. Devnet uses a test mint such as tUSD. Mainnet uses USDC and requires a separately reviewed production environment.

1. Prepare the server

Use a Linux server or Windows host with Docker. Create PostgreSQL separately; the application creates its tables but does not create the database.

Linux

sudo install -d -m 700 /opt/solana-recurring
sudo install -m 600 /dev/null /opt/solana-recurring/portal.env
sudoedit /opt/solana-recurring/portal.env

Windows PowerShell

New-Item -ItemType Directory -Force C:\ProgramData\solana-recurring
notepad C:\ProgramData\solana-recurring\portal.env

2. Configure Devnet

NODE_ENV=production
PUBLIC_BASE_URL=https://your-portal.example
DATABASE_URL=postgres://portal:CHANGE_ME@db-host:5432/portal?sslmode=require
SESSION_SECRET=GENERATE_A_LONG_RANDOM_VALUE
ADMIN_EMAILS=admin@example.com
SOLANA_CLUSTER=devnet
SOLANA_RPC_URL=https://api.devnet.solana.com
TOKEN_MINT=YOUR_DEVNET_TEST_SPL_TOKEN_MINT
TOKEN_DECIMALS=6
TOKEN_SYMBOL=tUSD
MERCHANT_SECRET_KEY=DEVNET_ONLY_SECRET
BILLING_ENABLED=true
PROVISIONER=noop

Use independent Devnet merchant and subscriber wallets. The merchant wallet needs Devnet SOL for fees; the subscriber needs the test token. Set PROVISIONER=litellm only when the LiteLLM test instance and dedicated admin key are ready.

3. Run the image

docker run -d --name solana-recurring --restart unless-stopped \
  -p 8080:8080 \
  --env-file /opt/solana-recurring/portal.env \
  ghcr.io/bzbwqz/solana-recurring:v0.2.0

On Windows, use --env-file "C:\ProgramData\solana-recurring\portal.env". Open the configured Portal URL, sign in as the invited administrator, publish a short test Plan, and test both subscription and fixed-credit flows.

4. Move to Mainnet

NODE_ENV=production
SOLANA_CLUSTER=mainnet-beta
SOLANA_RPC_URL=https://your-production-rpc.example
TOKEN_MINT=EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v
TOKEN_DECIMALS=6
TOKEN_SYMBOL=USDC
PROVISIONER=litellm
LITELLM_BASE_URL=https://your-litellm.example
LITELLM_ADMIN_KEY=DEDICATED_SERVER_SIDE_KEY

Use a production RPC provider, TLS, backups, secret storage, a low-balance merchant hot wallet, and enough SOL for worker fees. Enable ADMIN_WALLETS and keep the container running continuously.

Important: Plan accounts bind the cluster and token mint. Devnet Plans cannot migrate to Mainnet. Re-publish every production Plan after changing cluster or mint.

5. Understand the payment flows

  • Fixed credit: the user signs one direct USDC transfer; the server verifies recipient, mint, signer, amount, confirmation, and replay protection before granting entitlement.
  • Recurring Plan: the user signs subscription authorization once; the Portal worker alone submits each later transferSubscription and the provisioner updates LiteLLM.

Solana Pay URLs may be added later for QR or mobile-wallet handoff. They do not replace the current Portal verification or recurring Subscription PDA.
