AGENT 辅助部署

让 Agent 引导部署，生产控制权仍在你手中。

Deployment Operator Skill 可以规划、预检和验证 Portal 部署，但秘密和不可逆的支付动作始终由人控制。

必须先从 Devnet 开始。数据库、测试 mint、商户钱包、订阅用户钱包和 webhook secret 均需独立，绝不能复用于 Mainnet。

1. 安装 Skill

克隆或下载本仓库，并让 coding Agent 使用 skills/portal-deployment-operator/SKILL.md。私有源码仓库中也提供相同 Skill，位置为 .github/skills/。

2. 预检时不暴露秘密

Agent 可以生成 Docker 或 Bicep 模板、检查镜像 tag、运行构建、探测公开 health endpoint 和执行不泄露秘密的预检。私钥、数据库 URL、钱包材料、API key 和 webhook secret 必须由用户直接写入终端或云 Secret Store。Agent 只能报告配置是否存在。

pnpm deployment:doctor -- --config-file=/opt/solana-recurring/portal.env
pnpm deployment:doctor -- --production \
  --config-file=/opt/solana-recurring/portal.env \
  --health-url=https://portal.example.com/healthz

3. 生产确认闸门

生产变更前，检查镜像 tag/digest、公开 URL、cluster、mint、商户公开地址、收款地址、数据库主机、billing 状态、adapter 和 webhook 主机。部署、启用 billing、发布 Plan、重放 webhook 或 Mainnet 操作前，必须明确确认指明的生产目标。

4. 部署目标

Docker VM：使用固定镜像 tag/digest 和源码目录外权限为 600 的 env 文件。Azure App Service：使用 Key Vault reference 或 Application settings，设置 WEBSITES_PORT=8080 并启用 Always On。Azure Container Apps：使用 Key Vault 与 managed identity，ingress target port 设为 8080；在分布式 worker 协调验证前固定为一个 replica。

5. 部署后验证

检查 /healthz、容器 revision/image、公开 URL、通过应用健康状态验证的数据库连接、webhook 可达性和 worker 配置。健康容器不等于支付流程验收：进入 Mainnet 前仍要完成固定付款和周期订阅 Devnet 测试。

周期扣款边界：只有 Portal worker 可以提交 transferSubscription。Odoo、Agent 和下游服务可消费签名事件，但绝不能成为第二个 scheduler。
