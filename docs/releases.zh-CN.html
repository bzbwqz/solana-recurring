版本选择

按支付流程选择镜像。

只使用已发布且已验证的镜像 tag。源码 tag 存在但公共 container manifest 未发布时，不能视为可部署版本。

当前推荐生产版本：ghcr.io/bzbwqz/solana-recurring:v0.2.0。

版本矩阵

版本镜像状态适用场景主要能力
v0.1.0已发布需要原始最小 Portal 流程。邀请制登录、Wallet Standard 绑定、固定付款、周期 Plan、billing worker 与 LiteLLM Provisioning。
v0.2.0已发布，推荐需要稳定订阅与下游事件通知。包含 v0.1 全部能力，以及通用 webhook outbox、签名事件、重试和 Devnet webhook 验证。
v0.3.0源码 tag 已存在；公共镜像尚未发布暂时不要用于 Docker 部署。增加 Odoo 固定付款 intent Bridge；等待其已验证的公共镜像。
下一个已验证版本尚未发布需要 Odoo Bridge 与 Agent 辅助部署。将包含 Deployment Operator Skill、secret-safe Doctor、Docker Compose 和 Azure 起始模板。

部署已验证镜像

export PORTAL_VERSION=v0.2.0
docker pull "ghcr.io/bzbwqz/solana-recurring:${PORTAL_VERSION}"
docker run -d --name solana-recurring --restart unless-stopped \
  -p 8080:8080 \
  --env-file /opt/solana-recurring/portal.env \
  "ghcr.io/bzbwqz/solana-recurring:${PORTAL_VERSION}"

升级前检查

  1. 阅读新镜像的能力与配置要求。
  2. 使用独立 Devnet 数据库、测试 mint、钱包和 webhook secret 测试。
  3. 验证固定付款、周期扣款、webhook 投递和每个已启用 provider。
  4. 生产固定使用 tag 或 digest，不使用 latest。
  5. 变更 cluster 或 token mint 后必须重新发布 Plan。
周期扣款边界：只有 Portal worker 可以提交 transferSubscription。Odoo、Agent 和下游服务可消费签名事件，但绝不能成为第二个 scheduler。
