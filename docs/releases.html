VERSION SELECTION

Choose the image that matches your payment flow.

Use a published, verified image tag. A source tag is not deployable until its public container manifest is available.

Current production recommendation: ghcr.io/bzbwqz/solana-recurring:v0.3.0.

Deploy a verified image

export PORTAL_VERSION=v0.3.0
docker pull "ghcr.io/bzbwqz/solana-recurring:${PORTAL_VERSION}"
docker run -d --name solana-recurring --restart unless-stopped \
  -p 8080:8080 \
  --env-file /opt/solana-recurring/portal.env \
  "ghcr.io/bzbwqz/solana-recurring:${PORTAL_VERSION}"

Before upgrading

  1. Read the new image's capabilities and configuration requirements.
  2. Test it against a separate Devnet database, test mint, wallets, and webhook secret.
  3. Verify fixed payment, recurring collection, webhook delivery, and every enabled provider.
  4. Pin a tag or digest in production. Never use latest.
  5. Re-publish Plans after changing cluster or token mint.
Recurring payment boundary: only the Portal worker may submit transferSubscription. Odoo, Agents, and downstream services may consume signed events but never become a second scheduler.
